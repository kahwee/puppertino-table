# TypeScript usage

Start with your application's row model. `createPuppertinoColumnHelper<Asset>()` checks accessor keys and infers each cell's value: Size receives a number and Date Added receives a Date. Keep dates as Date values for chronological sorting; format them inside the cell.

## Write a typed Storybook story

Save this next to the example as `assets.stories.tsx`. Bind the generic component to your row model before passing it to `Meta`. Put required props in metadata args, and derive `StoryObj<typeof meta>` so each story inherits those defaults. Use `satisfies Story` to check overrides and infer play/decorator arguments. See [Storybook's TypeScript documentation](https://storybook.js.org/docs/writing-stories/typescript).

<Source language="tsx" code={`import type { Meta, StoryObj } from '@storybook/react-vite';
import { TableView } from 'puppertino-table';
import { type Asset, assetTableProps } from './typed-table-example';

const AssetTable = TableView<Asset>;
const meta = {
  title: 'App/Assets',
  component: AssetTable,
  args: assetTableProps,
  argTypes: {
    data: { control: false },
    columns: { control: false },
    density: { control: 'inline-radio', options: ['native', 'compact', 'comfortable'] },
  },
} satisfies Meta<typeof AssetTable>;
export default meta;
type Story = StoryObj<typeof meta>;

export const Playground = {} satisfies Story;
`} />

Use Controls for serializable behavior options. Columns contain functions and dates need deliberate construction; keep those fixtures in TypeScript. Change density, selection or disabled mode in the full canvas to explore the same component props your app will use.

## Args and controls

Use `satisfies Meta<typeof Component>` and `StoryObj<typeof meta>` to validate defaults and overrides. Keep serializable variants in args; label them with `argTypes`, categories and accurate defaults. Use conditional controls for dependent options. Keep React nodes, callbacks and column definitions in TypeScript.

For controlled components, use `useArgs` from `storybook/preview-api` in the story render function to update args when the component emits a change. Supply `fn()` from `storybook/test` for callbacks you want to inspect or assert. App selection, form values and view switches should update the same args that Controls edits.

Use the shared Theme global rather than a theme arg or a separate dark story. Keep regression-only stories tagged `['!dev', '!autodocs']`; they remain indexed and tested without filling the docs page. See [Args](https://storybook.js.org/docs/writing-stories/args), [ArgTypes](https://storybook.js.org/docs/api/arg-types) and [Tags](https://storybook.js.org/docs/writing-stories/tags).

## State ownership

Automatic sorting is the default. React-controlled sorting uses `SortingState` with `useState<SortingState>([])`; selection uses `RowSelectionState`. Set `manualSorting` when the app supplies an already ordered server page. External atoms and controlled props cannot own the same state slice. The package checks these conflicts at compile time.
