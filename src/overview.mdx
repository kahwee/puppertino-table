# Puppertino Table

Composable Finder workspaces, semantic React tables and independently resizable column browsers, with typed TanStack data and Puppertino styling. Start with a working app, then copy the public component recipes.

<Source language="tsx" code={`import { PuppertinoTable, createPuppertinoColumnHelper } from 'puppertino-table';
import '@codedgar/puppertino/colors';
import '@codedgar/puppertino/lists';
import '@codedgar/puppertino/forms';
import 'puppertino-table/style.css';

const helper = createPuppertinoColumnHelper<{ id: string; name: string }>();
const columns = helper.columns([
  helper.accessor('name', { header: 'Name', size: 280, minSize: 160 }),
]);
const files = [{ id: 'brief', name: 'Project brief.pdf' }];

export function Files() {
  return <PuppertinoTable data={files} columns={columns}
    getRowId={file => file.id} getRowLabel={file => file.name}
    ariaLabel="Files" density="compact" selectable />;
}`} />

## Choose the right ownership

Sorting automatically orders the supplied rows by default. Set `manualSorting` when supplying a server page or when your application owns row ordering. Sorting state ownership is independent: local sorting works with internal state, controlled values or external atoms.

The library owns table semantics, column/panel sizing gestures, selection primitives, density and menu behavior. Your app owns data fetching, folder routes, file moves, preview content and command authorization. Drag/drop in the Finder example uses native HTML events and in-memory state.

Omitted density inherits an enclosing `DensityScope` through CSS custom properties. Explicit presets start a new scope; partial metrics override just the supplied values. Scoped table rules require CSS `@scope` support: Chrome/Edge 118+, Safari 17.4+, Firefox 146+.

React 19 (`^19.3.0`), TanStack Table and Puppertino are peers. Import Puppertino's dark-mode CSS when using `.p-dark-mode`. No React provider is needed for density.
