# Finder walkthrough

Watch a gesture, try it in the app below, then copy the integration recipe. All files are fictional; moves update only the example's in-memory state. Videos have controls and never autoplay.

## File table

Click a sortable header, select checkboxes (Shift-click extends a range), and switch density or theme. Drag a divider, then double-click it to reset. Right-click a row for commands. **Reset demo** restores files, selection and widths while preserving your current view, theme and density.

Starting controls restart the workspace when changed. The in-app controls let you compare views and density while keeping your file moves. In a narrow docs canvas, the table scrolls horizontally; open the story in its own canvas to see the full desktop layout.

The recording drags the Name divider, double-clicks to reset it, then switches to Columns and resizes an ancestor panel. Focus a separator and use arrows (Shift for larger steps), Home/End for limits, or Enter to reset. Escape cancels an unfinished drag. Save preferences from completion callbacks, rather than every preview.

<Source language="tsx" code={`const [widths, setWidths] = useState({ workspace: 224 });
<ColumnBrowser panels={panels} ariaLabel="Projects"
  widths={widths} onWidthsChange={setWidths}
  onWidthsCommit={committed => savePreferences(committed)} />;`} />

Table resize options expose the matching `onCommit`. Supplying controlled widths without a change callback makes them read-only. <a href="./?path=/story/puppertino-resource-browser--controlled-panels" target="_top">Try controlled panels</a>.

## Column browser

Click a file to preview it. The two ancestor dividers resize independently; the current panel fills the remaining space. Panels have their own vertical scroll areas and the surface reveals the current panel horizontally.

<Canvas of={Finder.ColumnWorkspace} />

<Source language="tsx" code={`<DensityScope density="compact">
  <ColumnBrowser ariaLabel="Workspace" panels={[
    { id: 'folders', label: 'Folders', content: folderItems },
    { id: 'files', label: 'Project files', content: fileItems },
    { id: 'preview', label: 'Preview', content: <Preview file={selectedFile} /> },
  ]} />
</DensityScope>`} />

Use native `href` items for links or `onClick` items for buttons. Stable panel IDs preserve sizing. Give the browser a bounded height. Navigation and preview content belong to your app; a browser panel is not an automatic filesystem view.

  <a href="./media/context-menu.mp4">Download the context-menu screencast</a>
</video>

The recording opens a file menu at 125% zoom, chooses Get Info, then opens another menu with Shift+F10 and closes it with Escape. Focus a row before trying Shift+F10. Arrows/Home/End navigate enabled commands; disabled entries and separators are skipped. Escape restores focus to the invoking target. Shortcut hints are labels; your app binds any actual shortcuts.

<Source language="tsx" code={`const menu = useContextMenu<string>();
<ColumnBrowserItem {...menu.getTriggerProps(file.id)}>{file.name}</ColumnBrowserItem>
<ContextMenu ariaLabel="File actions" position={menu.state?.position ?? null}
  returnFocus={menu.state?.returnFocus} onClose={menu.close}
  actions={menu.state ? commandsFor(menu.state.context) : []} />;`} />

For tables, spread trigger props in `getRowProps` and include `tabIndex: 0`. Compose existing key handlers with the trigger's `onKeyDown`. Keep menus in the same themed subtree as their triggers. Commands and right-click selection policy stay caller-owned.

## Reduce integration code

For app-owned browser widths, keep `widths`, `onWidthsChange` and `onWidthsCommit`. For internally owned widths, pass just a `storageKey`:

<Source language="tsx" code={`<ColumnBrowser panels={panels} ariaLabel="Projects"
  storageKey="my-app.browser.widths.v1" />;`} />

Restoration waits until hydration; only completed gestures save. Hidden ancestors keep their preferences, and storage failures preserve browsing. Controlled widths ignore automatic persistence. <a href="./?path=/story/puppertino-resource-browser--persistent-panels" target="_top">Try persistent panels</a>.

A workspace can resolve menu contexts once rather than attaching handlers to every row:

<Source language="tsx" code={`const menu = useContextMenu<string>();
<div {...menu.getDelegatedTriggerProps({
  resolveContext: (target, root) => {
    const item = target.closest<HTMLElement>('[data-item-id]');
    const id = item?.dataset.itemId;
    return item && root.contains(item) && items.some(item => item.id === id) ? id : undefined;
  },
})}>{items.map(item => <ColumnBrowserItem key={item.id}
  data-item-id={item.id} aria-haspopup="menu">{item.name}</ColumnBrowserItem>)}</div>;`} />

Return no context for unknown items or editable fields to keep their native menus. The app still owns commands, selection and current-item validation. <a href="./?path=/story/puppertino-resource-browser--delegated-menus" target="_top">Try delegated browser menus</a> · <a href="./?path=/story/puppertino-resource-browser--delegated-table-menus" target="_top">Try delegated table menus</a>.

Use shared item slots and scoped CSS variables to customize presentation:

<Source language="css" code={`.my-browser {
  --pt-divider-color: var(--app-separator);
  --pt-icon-color: var(--app-accent);
  --pt-secondary-text: var(--app-secondary);
  --pt-item-gap: 8px;
}`} />

Selection preserves inherited icon and secondary-text contrast. <a href="./?path=/story/puppertino-resource-browser--custom-styling" target="_top">Try styling hooks</a> · <a href="https://github.com/kahwee/puppertino-table/blob/main/docs/guide.md#stable-item-styling-hooks-070" target="_blank" rel="noopener noreferrer">See the full token and slot reference</a>.
