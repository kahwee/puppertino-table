# Finder walkthrough

Compare all five Finder-style views, watch a gesture, then try it and copy the integration recipe. All files are fictional; moves update only the example's in-memory state. Videos have controls and never autoplay.

The window, toolbar, sidebar, view controls, search, action menus, icon/gallery layouts,
preview containers, tags and bottom bars are public exports. Start with the
[composition example](./?path=/docs/puppertino-finder-composition--docs) to build
your own Finder without importing demo modules. File data and operations stay in
your application.

## Playground

Use **View**, **Density** and **Selection checkboxes** in Controls instead of opening separate appearance stories. Change the shared **Theme** toolbar to compare light and dark. Click a sortable header, select rows (Shift-click extends a range), and switch density or theme. Drag a divider, then double-click it to reset. Right-click a row for commands. **Reset demo** restores files, selection and widths while preserving your current view, theme and density.

**View** and **Density** are synchronized with the in-app controls and preserve workspace state. **Select first preview** changes column preview setup without resetting files. **Table behavior** controls update selection, resizing, disabled state and sorting without resetting search or moved files. Table controls appear when the view is List; the first-preview control applies to Columns. Gallery always renders a preview. ## Outline in Finder

Choose **Outline** in the toolbar or Controls (`initialView="outline"`), or use Command/Ctrl+5. Groups expand with disclosure controls; Left/Right move through the hierarchy. File rows retain rename, Quick Look, context menus, drag/drop and shared selection. List and Outline use the same columns, sorting and width atom.

The example groups its current app-owned collection by kind; group rows are not selectable file commands. Collapsing a group preserves its file selection, while bulk commands only target currently exposed files. Search, tags, folder history and Trash remain app-owned. Expansion survives view changes.

## Select, organize and delete in bulk

Selection follows you between List, Icons, Columns and Gallery. Click a file to select it, Command/Ctrl-click to add or remove it, or Shift-click for a range. Choose **Select All** in the ellipsis menu or press Command/Ctrl+A. Enable the Selection checkboxes control in the playground to try optional row and header checkboxes; Finder examples hide them by default.

The bottom status bar shows the selection count. Open the toolbar’s ellipsis menu to move files to Archive or **Move to Trash**. Deletion is a menu command, never a standalone toolbar button. Right-click a selected file to apply a command to the selection; right-click an unselected file to act on just that file. Dragging a selected file moves the selected group to the destination folder or Trash.

**Undo Move to Trash** in the ellipsis menu restores the latest deleted batch. Open **Trash**, select files, and choose **Put Back** to return them to their original folders. Files remain fictional and in memory; reloading or **Reset demo** restores the starting workspace. Folder and search changes clear selection, so bulk actions never include hidden files.

## Tags

Select files and click the tag-shaped toolbar icon. The anchored Puppertino popover shows assigned tags as gray tokens in the input and unassigned tags underneath. Click a suggestion to assign it to the entire selection, or type a new name and press Enter. Click a token (or press Backspace in an empty input) to remove it. Escape closes the popover and restores focus to the toolbar button.

Sidebar tags filter files across Projects and Archive. Tags survive moves, Trash and Put Back; Reset demo clears them. Tags are app-owned state in `demo/finder-files.ts`, not part of the table API.

The chrome follows [Apple’s Finder toolbar reference](https://support.apple.com/guide/mac-help/customize-the-finder-toolbar-and-sidebar-mchlp3011/mac) and the supplied macOS screenshots: grouped icon controls, monochrome sidebar symbols, menu commands and a quiet bottom status bar. Puppertino supplies window, toolbar, sidebar and popover styles; Phosphor icons follow [Puppertino’s guidance](https://puppertino.com/docs/icons/), with regular toolbar symbols, filled selected views and duotone file-type icons.

The recording drags the Name divider, double-clicks to reset it, then switches to Columns and resizes an ancestor panel. Focus a separator and use arrows (Shift for larger steps), Home/End for limits, or Enter to reset. Escape cancels an unfinished drag. Save preferences from completion callbacks, rather than every preview.

<Source language="tsx" code={`const [widths, setWidths] = useState({ workspace: 224 });
<ColumnBrowser panels={panels} ariaLabel="Projects"
  widths={widths} onWidthsChange={setWidths}
  onWidthsCommit={committed => savePreferences(committed)} />;`} />

Custom table headers expose the matching `resizeOptions.onCommit`; individual resize handles use `options.onCommit`. The complete table exposes `onColumnSizingCommit` and saves internal widths with `storageKey`. Change callbacks observe previews (including cancellation); commit callbacks receive only completed snapshots. Supplying controlled widths without a change callback makes them read-only. <a href="./?path=/story/puppertino-column-view--column-workspace&args=widthMode:controlled" target="_top">Try controlled panels</a>.

<Source language="tsx" code={`<PuppertinoTable data={files} columns={columns} getRowId={file => file.id}
  ariaLabel="Files"
  onColumnSizingChange={observePreview}
  onColumnSizingCommit={savePreferences} />;`} />

Change observers work with internal state. Controlled state uses the same callback to apply updates; atom owners subscribe to their atom. <a href="./?path=/story/puppertino-table--resize-events" target="_top">Try resize events</a>.

The close-up recording opens a file menu, chooses Get Info, then opens another menu with Shift+F10, moves through commands with an arrow key and closes it with Escape. Focus a row before trying Shift+F10. Arrows/Home/End navigate menu items and skip separators. Disabled entries remain focusable for discovery but cannot activate. Escape restores focus to the invoking target. Shortcut hints are labels; your app binds any actual shortcuts.

<Source language="tsx" code={`const menu = useContextMenu<string>();
<ColumnBrowserItem {...menu.getTriggerProps(file.id)}>{file.name}</ColumnBrowserItem>
<ContextMenu ariaLabel="File actions" position={menu.state?.position ?? null}
  returnFocus={menu.state?.returnFocus} onClose={menu.close}
  actions={menu.state ? commandsFor(menu.state.context) : []} />;`} />

For tables, spread trigger props in `getRowProps` and include `tabIndex: 0`. Compose existing key handlers with the trigger's `onKeyDown`. Base UI portals prevent clipping; the wrapper retains the invoking control's light/dark theme and focus. Commands and right-click selection policy stay caller-owned.

## Reduce integration code

For app-owned browser widths, keep `widths`, `onWidthsChange` and `onWidthsCommit`. For internally owned widths, pass just a `storageKey`:

<Source language="tsx" code={`<ColumnBrowser panels={panels} ariaLabel="Projects"
  storageKey="my-app.browser.widths.v1" />;`} />

Restoration waits until hydration; only completed gestures save. Hidden ancestors keep their preferences, and storage failures preserve browsing. Controlled widths ignore automatic persistence. <a href="./?path=/story/puppertino-column-view--column-workspace&args=widthMode:persistent" target="_top">Try persistent panels</a>.

A workspace can resolve menu contexts once rather than attaching handlers to every row:

<Source language="tsx" code={`const menu = useContextMenu<string>();
<div {...menu.getDelegatedTriggerProps({
  resolveContext: (target, root) => {
    const item = target.closest<HTMLElement>('[data-item-id]');
    const id = item?.dataset.itemId;
    return item && root.contains(item) && items.some(item => item.id === id) ? id : undefined;
  },
})}>{items.map(item => <ColumnBrowserItem key={item.id}
  data-item-id={item.id} aria-haspopup="menu">{item.name}</ColumnBrowserItem>)}</div>;`} />

Return no context for unknown items or editable fields to keep their native menus. The app still owns commands, selection and current-item validation. <a href="./?path=/story/puppertino-column-view--column-workspace&args=menuMode:delegated" target="_top">Try delegated browser menus</a> · <a href="./?path=/story/puppertino-column-view--column-workspace&args=view:table;menuMode:delegated" target="_top">Try delegated table menus</a>.

Use shared item slots and scoped CSS variables to customize presentation:

<Source language="css" code={`.my-browser {
  --pt-divider-color: var(--app-separator);
  --pt-icon-color: var(--app-accent);
  --pt-secondary-text: var(--app-secondary);
  --pt-item-gap: 8px;
}`} />

Selection preserves inherited icon and secondary-text contrast. <a href="./?path=/story/puppertino-column-view--custom-styling" target="_top">Try styling hooks</a> · <a href="https://github.com/kahwee/puppertino-table/blob/main/docs/guide.md#stable-item-styling-hooks" target="_blank" rel="noopener noreferrer">See the full token and slot reference</a>.

## Finder keyboard behavior

Arrow keys move through files; Shift extends selection and typing jumps to a filename. Command/Ctrl+1–4 changes views, Space opens Quick Look, Escape closes it, and Return opens Rename. Column view uses Left/Right between folder and file panels. Double-click previews a file. Names and all commands remain application-owned. See the Keyboard Workflow story for an interactive walkthrough.
